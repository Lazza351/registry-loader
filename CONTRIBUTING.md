# Участие в разработке

Ошибки описывайте в Issue с минимальным воспроизводимым примером. Крупные изменения лучше сначала обсудить. Уязвимости сообщайте по [SECURITY.md](SECURITY.md), а не через публичный баг-репорт.

## Разработка и проверки

Нужны Linux, Python 3.11–3.14 и uv. Docker Engine и Compose plugin нужны для контейнерных проверок; настоящий Nexus для обычных тестов не требуется.

```bash
uv sync --frozen
uv run --frozen ruff check src tests
uv run --frozen ruff format --check src tests
uv run --frozen pytest -q --cov=nexus_uploader --cov-report=term-missing
uv build

docker compose --env-file .env.example config --quiet
docker build -t registry-loader:test .
docker run --rm registry-loader:test --check-config
```

При изменениях зависимостей сохраняйте верхние границы версий и обновляйте `uv.lock` через `uv lock`. `--check-config` проверяет настройки, но не соединение с Nexus. Изменения транспорта дополнительно проверяйте на изолированных registry/PyPI-сервисах, не production.

## Pull request

- Делайте небольшие самостоятельные изменения с описанием причины.
- Добавляйте поведенческие регрессионные тесты; не используйте production credentials.
- Сохраняйте гарантии очереди: исходник не теряется при ошибке, частичная копия не загружается, чужой terminal-каталог не перезаписывается, секреты не попадают в логи.
- Учитывайте at-least-once: не обещайте exactly-once и атомарность нескольких тегов.
- Обновляйте README и `.env.example`, если меняется конфигурация.
- Не коммитьте `.env`, PAT, пароли, приватные ключи, рабочие архивы и данные очереди.
- Указывайте реально выполненные проверки и ограничения.

Общайтесь уважительно, обсуждайте решения, а не личные качества участников.
Предлагая изменения, вы соглашаетесь на их распространение по [MIT](LICENSE).
Сохраняйте уведомления об авторстве и лицензии стороннего кода; CLA не требуется.
