# Безопасность

## Поддерживаемые версии

Исправления безопасности в первую очередь вносятся в актуальную ветку `main`. Отдельный срок поддержки старых версий и гарантированный SLA не заявлены.

## Сообщение об уязвимости

Не публикуйте описание эксплуатации, credentials, `.env`, приватные архивы или чувствительные логи в публичном Issue/PR.

Если на GitHub в **Security → Advisories** доступна кнопка **Report a vulnerability**, используйте её для закрытого сообщения. Наличие функции зависит от настроек репозитория; этот документ её не включает.

Если закрытая форма недоступна, создайте Issue только с просьбой предоставить приватный канал связи, без деталей уязвимости и секретов. Дождитесь согласования канала с владельцем. В закрытом сообщении укажите ревизию, условия воспроизведения, влияние и минимальный обезличенный пример.

При утечке токена/пароля сначала отзовите или замените его: удаление из текущего файла не удаляет секрет из истории Git, чата или логов.

## Безопасное развёртывание

- Предпочитайте HTTPS и проверку TLS; корпоративный CA задавайте через `CA_BUNDLE`. Отключайте проверку только как осознанное исключение.
- Используйте отдельную учётную запись Nexus с минимальными правами.
- Не публикуйте вывод `docker compose config` с подставленными credentials; используйте `config --quiet`.
- Храните `.env` с ограниченными правами, не включайте в Git/build context. Environment контейнера доступен администраторам Docker: это не secret vault.
- Не монтируйте Docker socket. Не запускайте сервис privileged/root без необходимости.
- Доступ на запись в input/processing/success/error оставляйте только доверенным процессам. Очередь не является песочницей для атакующего с тем же UID/правами.
- Публикуйте готовые файлы через временное имя и atomic rename; не перезаписывайте необработанные файлы и не продолжайте запись после публикации.
- Планируйте свободное место и retention: сжатые образы требуют дополнительного диска, success/error автоматически не очищаются.
- Учитывайте at-least-once и частичный успех нескольких тегов; проверяйте `result.json`.

Особенности TLS, NFS и восстановления описаны в [README](README.md).
